# ugnas-bridge v2 部署手册（FastAPI 版）

> 适用 v2.0.0 起（Python 3.11+ + FastAPI + SQLite）。管理台与桥接同端口、同进程。

## 1. 两种交付方式

### 1.1 Docker（推荐）
```bash
docker run -d --name ugnas-bridge -p 8770:8770 \
  -e UGNAS_BRIDGE_KEY='<32位口令>' \
  -e UGNAS_BRIDGE_BASE='http://<本机或域名>:8770' \
  -v ugnas-state:/app/state -v ugnas-logs:/app/logs \
  ghcr.io/sundada1453/ugnas-bridge:latest
```
- 镜像内置前端（COPY web/static）；必须挂 state 卷。
- 多架构：linux/amd64 / linux/arm64。

### 1.2 裸机（systemd）
```bash
git clone -b v2 https://github.com/sundada1453/ugnas-bridge.git
cd ugnas-bridge && sudo bash deploy/install.sh
```

## 2. 首次配置
1. 打开 `http://<host>:8770/` → 设置管理口令（≥8 位）。
2. 绿联 NAS：地址/用户名/密码 → 测试连接（真实登录，10s 冷却）。
3. Sun-Panel 两级：OpenAPI token（必填）+ 管理员账号（可选，解锁删除）。
4. 应用清单 → 一键发现 → 同步任务 → 四态预览 → 勾选 → 执行。

## 3. 运行参数
| 变量 | 默认 | 说明 |
|---|---|---|
| UGNAS_BRIDGE_PORT | 8770 | 监听端口 |
| UGNAS_BRIDGE_KEY | 空 | /open/* 的 ?k= 口令 |
| UGNAS_BRIDGE_BASE | 空 | 卡片链接基址 |
| UGNAS_BRIDGE_DB | state/ugnas_bridge.db | SQLite |
| UGNAS_LOG_DIR | logs | 日志目录 |
| UGNAS_HEALTH_INTERVAL | 300 | 健康探测间隔 |
| UGNAS_DEMO_AUTH | 未设 | 仅本地截图，生产禁止 |

## 4. 接口
- 管理台 `/`；`/api/login`、`/api/setup`
- 配置 `GET/POST /api/config/{ugreen|sunpanel|sunpanel_admin}`
- 测试 `POST /api/test/ugreen|sunpanel`（前端 10s 限速）
- 发现 `GET /api/apps`、`POST /api/apps/manual`、`POST /api/discover/run`
- 同步 `POST /api/sync/preview|apply|rollback`
- 健康 `GET /api/health`、`/api/health/detail`、`POST /api/health/run`
- 免登录 `GET /open/{port}?k=<KEY>` → 302

## 5. 验收自检
```bash
python3 scripts/verify.py --base http://127.0.0.1:8770 --key <口令>
```

## 6. 部署纪律
- **systemd unit 落盘后先 `ss -lntp | grep <端口>` 核对端口归属再 `systemctl start`**（曾因 unit 端口写错与旧服务冲突）。
- 升级切换：先 `systemctl disable --now 旧服务`（文件保留），再启动新服务，最后核对监听与 `/api/health`。

## 7. 已知限制
- 官方 OpenAPI 无「卡片列表/删除/分组删除」：走 `sunpanel/internal.py`（非官方契约，仅 1.8.1 实测），升级只改该文件。
- 删除卡片需配置管理员账号；默认只提供移回收站，删除二次确认。
- ghcr.io 在部分国内云默认网络不可达；此类环境用裸机安装或自配镜像源。
- UGNAS_DEMO_AUTH 仅开发截图用，生产勿设。
