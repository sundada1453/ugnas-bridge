# ugnas-bridge v2 部署手册（FastAPI 版）

> 适用 v2.0.0 起（Python 3.11 + FastAPI + SQLite）。管理台与桥接同端口、同进程。

## 1. 两种交付方式

### 1.1 Docker（推荐）
```bash
docker run -d --name ugnas-bridge -p 8770:8770 \
  -e UGNAS_BRIDGE_KEY='<32位口令>' \
  -e UGNAS_BRIDGE_BASE='http://<本机或域名>:8770' \
  -v ugnas-state:/app/state -v ugnas-logs:/app/logs \
  ghcr.io/sundada1453/ugnas-bridge:latest
```
- 镜像**已内置前端**（`COPY web/static`），访问 `http://<host>:8770/` 即管理台。
- 必须挂 `-v ...:/app/state`，否则配置库（加密）与同步快照会随容器重建丢失。
- 多架构：`linux/amd64`（x86 服务器）、`linux/arm64`（绿联 ARM NAS）。

### 1.2 裸机（systemd）
```bash
git clone -b v2 https://github.com/sundada1453/ugnas-bridge.git
cd ugnas-bridge && sudo bash deploy/install.sh
```
- 脚本会建 venv、装 `requirements.txt`（fastapi/uvicorn/requests/cryptography/websocket-client）、生成 `/etc/ugnas-bridge.env`（含 32 位口令）、装 `ugnas-bridge.service` 并启动。
- 日志：`/opt/ugnas-bridge/logs/bridge.log`（按 5MB 轮转，保留 5 份）。

## 2. 首次配置（管理台）

1. 打开 `http://<host>:8770/` → 首次设置管理口令（≥8 位，PBKDF2 存哈希）。
2. **设置 → 绿联 NAS**：访问地址（`https://xxx.ug.link` 或 `https://<nas>:9443`）、用户名、密码 → 测试连接（真实登录，前端 10 秒冷却）。
3. **设置 → Sun-Panel 两级配置**：
   - **OpenAPI Token（必填）**：面板 `设置 → OpenAPI` 生成，用于创建/更新卡片、读取分组。
   - **管理员账号（可选）**：填了才解锁「删除卡片/深度管理」；不填则只能「移回收站」。均加密落盘、不回显。
4. **设置 → 健康监测**：填写 NAS 内网 IP 或 Tailscale IP（如 `100.111.245.21`），用于端口可达性探测；未配置时仪表盘显示「未探测」，不会伪造绿色状态。
5. 保存后进「应用清单」一键发现 → 「同步任务」刷新四态预览 → 勾选 → 执行同步。

## 3. 运行参数（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| UGNAS_BRIDGE_PORT | 8770 | 监听端口 |
| UGNAS_BRIDGE_KEY | 空 | `/open/*` 的 `?k=` 口令；生产必须设置 |
| UGNAS_BRIDGE_BASE | 空 | 生成卡片链接的桥接基址（如 `http://1.2.3.4:8770`） |
| UGNAS_BRIDGE_DB | state/ugnas_bridge.db | SQLite 路径 |
| UGNAS_LOG_DIR | logs | 日志目录 |
| UGNAS_HEALTH_INTERVAL | 300 | 健康探测间隔（秒） |
| UGNAS_DEMO_AUTH | 未设 | **仅本地截图用**，=1 跳过鉴权；生产禁止设置 |

## 4. 接口一览

- 管理台：`/`（需登录）；`/api/login`、`/api/setup`
- 配置：`GET /api/config`（脱敏）、`POST /api/config/{ugreen|sunpanel|sunpanel_admin|health}`、`DELETE /api/config/{kind}`
- 测试：`POST /api/test/ugreen`、`POST /api/test/sunpanel`（前端限速 10s/次）
- 发现：`GET /api/apps`、`POST /api/apps/manual`、`POST /api/discover/run`
- 同步：`POST /api/sync/preview`、`POST /api/sync/apply`、`POST /api/sync/rollback`
- 健康：`GET /api/health`、`GET /api/health/detail`、`POST /api/health/run`
- 免登录：`GET /open/{port}?k=<KEY>` → 302 到应用一次性授权地址

## 5. 验收自检
```bash
python3 scripts/verify.py --base http://127.0.0.1:8770 --key <口令>
```
配置前只会跑 health；配置后追加 open 401/302 检查。

## 6. 部署纪律
- **systemd unit 落盘后先 `ss -lntp | grep <端口>` 核对端口归属再 `systemctl start`**；历史上曾因 unit 端口写错与旧服务冲突（已纳入教训）。
- 升级切换顺序：先 `systemctl disable --now 旧服务`（文件保留），再启动新服务，最后核对监听与 `/api/health`。

## 7. 已知限制
- 官方 OpenAPI 无「卡片列表/删除/分组删除」：expired 枚举与删除走 `sunpanel/internal.py`（非官方契约，仅 1.8.1 实测），面板升级只改该文件。
- 删除卡片需配置管理员账号；默认只提供移回收站，删除二次确认。
- **面板若未开启公开访问，需配置管理员账号**才能枚举卡片做四态预览；不配则预览显示本地快照并禁止 apply（防止重复建卡）。
- `UGNAS_DEMO_AUTH` 仅开发截图用，生产勿设。
