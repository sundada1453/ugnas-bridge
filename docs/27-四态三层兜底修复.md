# 四态三层兜底修复（v2.0.1 · 2026-10-31）

> 背景：用户实测反馈（1）同步执行面板卡片无变化；（2）sub2api 8080、g-box 4567、claude-code-proxy 18082、hermes 19119 等十几张卡被误判过期，但逐张验证能打开。

## 1. 根因

`web/api/sync.py` 之前只把 `apps` 表作为发现端口集：
- UGOS Docker API 对 host 网络容器的 `portMapping` 为空；
- 容器扫描有漏网（host PID/netns 与容器 PID 命名空间差异）；
- 因此 `apps` 端口集缺少 host 网络/非容器端口，四态 `diff()` 直接按「端口不在发现集」判 `expired`；
- v1 遗产 26 张卡中 8 张旧卡 + 4 张宿主服务卡被误伤（sub2api 8080 在部分时点 apps 记录也被覆盖为空）。
- `apply` 实际调用 `SunPanelClient.update_item/create_item` 本身可用；之前用户点击时没有可执行操作（过期默认「跳过」或数据源过期），所以看起来「没生效」。

## 2. 修复

### 2.1 三层端口兜底（`web/api/sync.py` + `discover/host_probe.py`）
1. **容器发现端口集**：现有 `apps` 表（portMapping / container-scan）。
2. **NAS 宿主 TCP 探测**：通过 `tailscale` 容器（`networkMode=host`，netns=宿主）读取 `/proc/net/tcp{,6}` 的 `LISTEN(0A)` 端口，缓存 120s；`host_probe` 结果注入 diff 的 `manual_ports` 池，不在发现集但宿主在监听的端口不判 `expired`。
3. **health 探测结果**：`health` 表中 `up=1` 的端口同样注入 live 池。

### 2.2 v1 遗产保护
- `state/cards_state.json`（v1 快照）里的 `ugnas-<port>` 卡加入 protected 池：即使当前发现集没有对应端口，也不判过期、不进入清理建议。
- 仅管理 `^ugnas-<数字>$` 卡；用户原生卡（`gb-*` 等）与 `ugnas-desktop` 不进入四态，避免误删/误改。
- 新增 `skipped_unmanaged` 计数随预览返回，便于审计。

### 2.3 同步执行
- 真实面板验证 `apply`：
  - 新建测试卡 `ugnas-65533` → QA 分组，回读 `itemGroupID=24`、URL 为 `/open/65533?...`，`create ok1/fail0`；
  - 测试卡 `ugnas-65534` 改标题/URL，`update ok1/fail0`，回读标题和 URL 均为新值；
  - 测试卡与分组已清理，用户 27 张卡/12 分组未动。
- `apply` 响应错误提示/分组参数均可用；前端成功提示已确认保留。
