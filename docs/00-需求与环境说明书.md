# 绿联 NAS ⇄ Sun-Panel 免登录直连 · 需求与环境说明书（v2）

> v1 开发的需求源头文档，供 v2 开发参考。

---

## 0. 一句话目标

在 **Sun-Panel 导航面板**里，点绿联 NAS 的任意容器卡片，**直接进入该应用 Web 界面，免登录、无二次跳转**。只能走绿联官方域名通道（`*.ug.link` / `*.ugdocker.link`），不得改用 Cloudflare 或任何其它通道。

---

## 1. 需求与验收

### 1.1 现状
- Sun-Panel 已有分组「绿联NAS」（`itemGroupID=13`, `onlyName=ugreen-nas`），共 **27 条卡片**：1 条「UGOS 桌面」+ 26 条容器应用。
- 每条 `lanUrl = http://<NAS_IP>:<端口>`（内网直连可用）；`url`（公网）原为占位桌面入口，点开要登录，不达标。

### 1.2 目标
- 点任意卡片 → 3 秒内直达应用首页，**无绿联登录框、不跳桌面**。
- token 过期自动续，用户无感。
- 不可达时明确报错，不白屏。

### 1.3 约束
- 只用绿联官方通道；卡片写入走 Sun-Panel OpenAPI；不新建 Docker；密钥不写明文。

## 3. 逆向结论（从 `BlackHolesYvan/ugport` 源码逐行确认）

### 3.1 ugport 的真实架构
**ugport 是一个 Android App，仓库里没有任何服务端。** 它的“中转”全部编在 App 内部：

1. App 用 Android Keystore 加密保存账号密码。
2. 登录拿 keepalive token：优先 WebView 加载绿联官方登录页 → JS 自动填表 → 从 `localStorage['accessInfo']` 取 `api_token`；也实现 HTTP 登录兜底。
3. 点端口卡片时 App 内部调 `dockerToken` 拿一次性 `redirect_url`，WebView 打开 → 自动落 `ugreen-proxy-token` cookie → 进入 `app-<port>-1/`。

⇒ **换 token 这一步客观存在，但它是 App 内的一行代码，不是一台服务器。**

### 3.2 必须携带的客户端头
```
User-Agent:          Chrome/131 桌面 UA
Accept:              application/json, text/plain, */*
Accept-Language:     zh-CN,zh;q=0.9,en;q=0.8
Origin / Referer:    认证入口 + /desktop/
Client-Id:           <随机 uuid4>-WEB      ← 随机 UUID，不是固定值
Client-Version:      78578
Client-Version-Str:  1.20.0
UG-Agent:            PC/WEB
X-Specify-Language:  zh-CN
```

### 3.3 登录接口（HTTP 路）
```
POST /ugreen/v1/verify/check {username} → 响应头 X-Rsa-Token = base64(PEM)
     PEM 标 "BEGIN RSA PUBLIC KEY" 实为 SPKI：先按 X509 解析，失败再手解 PKCS#1
     加密 RSA/ECB/PKCS1Padding，密文 base64
POST /ugreen/v1/verify/login
     {username, password: <密文>, keepalive, otp, is_simple}
     → data.token / data.enable_otp / data.token_id / data.otp_type / data.public_key
若 enable_otp → POST /ugreen/v1/verify/code/login
     {code, type, token_id, trust_info, trust:true}
```

### 3.4 token 之后（v1 旧协议，固件 <1.21）
```
GET /ugreen/v1/verify/is_login?token=…        → 200 有效 / 1024 过期
GET /ugreen/v1/docker/app/GetUid?token=…      → data.result | data.uid
GET /ugreen/v1/docker/app/dockerToken?port=…&token=…  → data.redirect_url（一次性）
GET <redirect_url>                            → Set-Cookie: ugreen-proxy-token=…
带该 cookie 访问 https://<alias>.<dockerDomain>/app-<端口>-1/  → 免登录
PUT /ugreen/v1/verify/refresh?token=…          → 续期
```

### 3.5 为什么静态 URL 做不到免登录
- `redirect_url` 是**一次性、需 token 动态生成**，不能预生成写进卡片。
- 裸端口不可达（中继只开 443/80/9443）。
- ⇒ 每点一次都必须“现调 dockerToken 换新 redirect_url → 让浏览器打开它落 cookie”。

## 4. 载体选型（v1 结论：B 本地/公网小服务）

| 载体 | 结论 |
|---|---|
| A. 浏览器扩展 / 油猴 | 零服务器但覆盖不了手机，可作桌面叠加 |
| **B. 本地/公网小服务** | **v1 选用**：任何浏览器/设备可用，纯 HTTP 几十行代码 |
| C. App / PWA | 成本最高 |
| D. 静态跳板页 | 不可行（CORS + cookie 域） |

## 8. 过程教训（供 v2 规避）
1. 不查密钥库就反复要密码；
2. HTTP 1005 卡住就想换 Cloudflare 改需求（最严重）；
3. 没先读 `LoginScripts.kt` 就死磕 HTTP API，误判“需要中转服务”——实为 App 内置；
4. 把 Sun-Panel 的 admin 当 UGOS 账号；
5. 固件升级（1.21）后旧协议资料全失效，**必须真实抓包**。
