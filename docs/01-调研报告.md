## 二、第 1 步：真实浏览器抓包（Playwright + Chromium 155）

页面：`https://<ALIAS>.cn91.ug.link/desktop/#/login/account`（`data-version=1.21.0.80330`）

### 2.1 `POST /ugreen/v1/verify/check`
- 请求体：`{"username":"<USER>"}`（**POST，JSON**）
- 响应头：`X-Rsa-Token: base64(PEM)`；头写 `BEGIN RSA PUBLIC KEY`，实为 **SPKI**（先按 X509 解，失败再 PKCS#1）
- 响应体：`{"code":200,"msg":"success"}`

### 2.2 `POST /ugreen/v1/verify/login`（真实字段）
```json
{"username":"<USER>","[secret:UGREEN_NAS_PASS]":"<RSA-PKCS1v15(base64)>","keepalive":false,"otp":true,"is_simple":true,"support_force_otp":true}
```
响应 `code=200`，`data` 含：
`token`(32) / `token_id`(32) / `static_token` / `third_token` / `public_key`(base64 PEM，供 V2 加密) / `auth_type=header` / `enable_otp=false` / `uid=1000` / `model=DH4300 Plus` / `system_version=1.21.0.0190`

**无 OTP 弹窗**，一次登录直接进桌面。

### 2.3 关键请求头（Web 端）
`client-id: <uuid>-WEB`、`client-version: 80330`、`client-version-str: 1.21.0`、`ug-agent: PC/WEB`、`x-specify-language: zh-CN`、`Origin: <base>`、`Referer: <base>/desktop/`

## 三、第 2 步：全链路（纯 Python，无浏览器）

### 3.1 链路
```
login → is_login(200) → GetUid(200) → dockerToken(V2) → redirect_url
      → GET redirect_url(HTML) → 解析 ugreen-proxy-token → 自设 cookie
      → GET https://app-<port>-<ALIAS>.cn91.ugdocker.link/ → 应用首页 200
```

### 3.2 V2 换 token 的真实做法（本固件核心发现）
```
GET /ugreen/v1/gateway/proxy/dockerToken?port=<port>
Headers:
  x-ugreen-token:        base64( RSA_PKCS1v15( utf8(token), NAS公钥 ) )   ← 344 字符
  x-ugreen-security-key: <login 返回的 token_id>                          ← 32 字符
```
- 缺 `x-ugreen-security-key` → `code=9405`
- `x-ugreen-token` 传明文 token → `code=1010 Token不可为空`
- `x-ugreen-token` 用 RSA-OAEP → `1010`；**必须 PKCS1v15**
- 旧接口 `/ugreen/v1/docker/app/dockerToken` 在本固件固定 `9405`（已废弃）

响应：
```json
{"code":200,"data":{"redirect_url":"https://app-8097-...ugdocker.link/api/ugreen/auth?token=..."}}
```

`redirect_url` 返回的是一段 HTML，用 JS 写 cookie：
```
document.cookie='ugreen-proxy-token=<raw>; Path=/; Domain=app-<port>-<ALIAS>.ugdocker.link; Secure; SameSite=None'
```
**纯 Python 直接正则提取该值并自设 cookie 即可**，不需要执行 JS。

## 四、第 3 步：token 生命周期与 refresh

- 登录 token 32 字符；`keepalive=true/false` 返回的 token 形态一致。
- `PUT /ugreen/v1/verify/refresh?token=<token>` → `code=200 success`，**data 为空**（服务端原地续期，不换新 token）；refresh 后 `is_login` 仍 200。
- `refresh` 必须 **PUT + query token**；放 `x-ugreen-token` 头 → `1010`；用 GET → `9404`。
- 失效判定：`is_login` 返回 `1024` 即过期，此时重新走一次登录即可（登录 0.5s）。
- 未发现显式 TTL 字段；建议本地服务每 30–60 分钟调一次 `refresh`，遇 `1024/1010/9405` 自动重登。

## 六、载体选型判断

| 载体 | 判断 |
|---|---|
| **B 本地小服务** | **首选**。换 token 已证明是纯 HTTP（无浏览器、无 CORS 问题），一个 30–80 行的服务即可 `/open/<port>` 302。局域网内电脑/手机通吃；出门走 Tailscale 或公网主机 |
| A 扩展/油猴 | 可作桌面快捷入口叠加；但受 CORS（ACAO 只回 `https://www.ug.link`）与 `Secure; SameSite=None` cookie 限制 |
| C App/PWA | 成本最高，B 已够用 |
| D 静态页 | 不可行（CORS + cookie 域） |
