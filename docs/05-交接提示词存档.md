# 交接提示词 · 绿联 NAS ⇄ Sun-Panel 免登录直连（v1 归档）

> 本文件是 v1 开发过程的交接指令存档，供 v2 开发参考。

---

## 给统筹方的指令

```
【任务】绿联 NAS ⇄ Sun-Panel 免登录直连。需求与环境见需求与环境说明书.md。

【一句话】让 Sun-Panel 导航里点任意绿联容器卡片直达应用、免登录，
只走绿联官方域名通道（*.ug.link / *.ugdocker.link），等价复刻开源项目 BlackHolesYvan/ugport 的原理。

【硬约束】
1. 派架构师先调研+POC，出方案与可行性结论。
2. 审方案是否偏离“只用绿联通道 + 不做多余公网中转”，再让人开发。
3. 盯到 3 个以上端口点开即免登录进应用才算验收。
4. 不新建 Docker、不动用户 Windows、密钥不落明文、不代用户对外发消息。

【卡点提示】换一次性 token 是“客户端载体”问题，不是必须加服务器：ugport 做进了 App。
```

## 给开发方的指令

```
【任务】为 Sun-Panel 绿联容器卡片做“点开免登录直达”，先调研再 POC。

【硬约束】
- 只走绿联官方通道（*.ug.link / *.ugdocker.link），不得引入 Cloudflare 或其它通道。
- 不要因为“要换 token”就默认加公网中转服务器，先做载体选型调研。
- 卡片写入用 OpenAPI，读回用 item/getInfoByOnlyName。
- UGOS 用户密码取环境变量，绝不写明文/打日志。

【必须先验证的 4 件事】
1. 真实浏览器打开 https://<ALIAS>.ug.link/desktop/ 登录，抓包确认 /ugreen/v1/verify/login 真实字段、是否弹 OTP。
2. 手动走通 is_login→GetUid→dockerToken→redirect_url→Set-Cookie→app-<port>-1/ 全链路。
3. 确认 token 生命周期与 refresh 行为。
4. 验证 Sun-Panel 单条卡片 url 可改（试一条，测完回滚）。

【POC 验收】≥3 个端口点开即进应用首页（UGOS 层无登录框）；token 过期自动续；
产出方案文档+POC 代码+改卡脚本+回滚办法，全部写明绝对路径。
```
